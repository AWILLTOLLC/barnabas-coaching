## VantageOC Server-Side Changes (Major Session)

### Bug Fix: Reply Routing
- Root cause found: `updateLastRoute` was using `sessionKey: 'main'` but the actual store key is `'agent:main:main'`
- `normalizeStoreSessionKey` is just `.toLowerCase()` — doesn't resolve aliases
- Fix: changed to `sessionKey: 'agent:main:main'` → replies now correctly route to Vantage instead of Telegram
- Also added `'main'` to PROTECTED channels in `vantage.channels.delete`

### Architecture Change: Ping + Cursor-Based Poll
Old model: `pushEnvelope` broadcast full message content to all WS clients via `_broadcast`.
Problem: `_broadcast` is global — all connected clients got every message, causing doubles.

New model:
- `pushEnvelope` now broadcasts only a lightweight ping: `{ type: 'vantage.new', ts: <unix ms> }`
- Clients call `vantage.poll` with `{ since: <cursor> }` to fetch actual events (non-destructive)
- Each client owns its cursor → no duplicates possible from multiple clients
- Cursor must be advanced BEFORE rendering, locked during in-flight polls

### Other Changes Implemented
- `store.pollSince(since, limit, channelSlug)` — cursor-based non-destructive poll
- `store.purgeOldEvents(maxAgeMs)` — 24h retention, called on gateway.start + every 6h
- `vantage.channels.mark_read` now enqueues `channel_read` event for cross-client badge sync
- `loopbackChatSend` updated to accept `attachments` param, passes to `chat.send`
- Inbound operator messages now persisted to `channel_messages` + enqueued before `loopbackChatSend`
- `channel_read` added to `MessageType` in types.ts
- Old `dequeue`/`peekQueue` deprecated (kept for backward compat)

### Design Decisions
- Telegram and Vantage are completely separate channels — never cross-post, last-sender-wins routing is correct
- Multiple Vantage clients (iOS + macOS future) share same channel — all get ping, each polls with own cursor
- Client-side dedup by msgId NOT required with ping+cursor model
- Operator inbound messages: persist silently to history, DO push to queue (fires ping for cross-device sync)

### Transcript Poisoning Bug (Discovered + Resolved)
- Early in session, the old broadcast model sent full message content to all WS clients
- This caused doubled text to be stored in the agent transcript (e.g., "Done.\n\nDone.")
- LLM (Dru) then MIMICKED the doubled pattern in subsequent responses → self-reinforcing loop
- Escalated: double → triple as pattern compounded
- Fix: session reset cleared poisoned transcript → clean output resumed
- Key lesson: if response text doubles/triples, check transcript immediately — it's likely poisoned

### Client-Side Required Changes (for Vantage macOS)
1. Stop rendering from `vantage.event` broadcasts (now ping-only, no content)
2. On `vantage.new` ping or connect: call `vantage.poll?since=<cursor>`
3. Advance cursor atomically before rendering — lock during in-flight poll
4. Initialize cursor to `Date.now()` on fresh install (not 0)
5. Persist cursor to UserDefaults
6. Handle `channel_read` events (clear badge) and `sender: 'operator'` chat events (render as outbound)

### [2026-03-08] Ping-only broadcast + cursor poll eliminates multi-client duplicates

**Context:** Any plugin delivering events to multiple WebSocket clients simultaneously.
