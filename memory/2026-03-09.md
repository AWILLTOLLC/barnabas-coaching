### Plugin SDK Notes
- `api.registerHook(event, handler, opts)` — handler is `(event: InternalHookEvent) => void`, single arg
- `api.on(event, handler)` — typed lifecycle hooks with two-arg handler (event, ctx)
- `PluginHookName` type uses underscores: `"message_sent"`, `"message_received"` etc.
- BUT `api.registerHook` uses colon format: `"message:sent"` (InternalHookHandler style)
- `channelId` in message:sent hook lives at `event.context.channelId`

### Critical Lessons Learned — Hook System
1. **`before_message_write`** — wired ONCE at session setup via `guardSessionManager()`. If no typed hooks registered yet at that moment → `beforeMessageWrite = void 0` permanently for that session. DO NOT use for mirroring.
2. **`message:sent` internal hook** — only fires for EXTERNAL channels (Telegram, WhatsApp, etc.), NOT webchat. Webchat delivers directly over WebSocket, bypassing `deliverOutboundPayloads()`.
3. **`llm_output` typed hook** — `hasHooks()` checked LIVE per-turn. Always picks up registered handlers. ✅ CORRECT approach.
4. **`before_message_write` session key** — the session key is in `ctx` (second handler arg), not `event`. `event.sessionKey` is always `undefined`.
5. **Typed hooks vs internal hooks**: `api.on()` → `registry.typedHooks[]` (typed, checked live). `api.registerHook()` → `registry.hooks[]` (internal, wired at setup). Different arrays, different invocation paths.

### Broadcast Dual-Path Fix (23:49 UTC)
- After restart, `_broadcast` in `rpc.ts` is null until the first RPC call comes in
- `getBroadcast()` returns null on first turn after restart → silent no-op
- Fix: broadcast via BOTH `broadcast()` from `broadcast.ts` (SSE clients) AND `getBroadcast()` from `rpc.ts`
- Direct SSE path works as long as client has `/vantage/events` connection
- If client's SSE connection also dropped on restart, neither path works — client needs to reconnect SSE
