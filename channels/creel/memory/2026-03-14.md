# Session Log — 2026-03-14

## Agents Channel Native Posting — Full Fix

### Problem
`message(action=send, channel=vantage, target=clubhouse)` was throwing "Unknown target" and agents had no native way to post to the agents channel.

### Root Causes Found (3 separate bugs)

1. **Wrong routing layer** — The `channel.ts sendText()` fix was correct in concept but the error happened *upstream* of it. The gateway's `resolveMessagingTarget` function did a directory lookup for `clubhouse`, found nothing, and returned `unknownTargetError` before `sendText()` was ever called.

2. **`extractMentions` regex bug** — Space character in char class `[A-Za-z0-9 _-]` caused the regex to consume entire sentences as a single mention (e.g., `@Dru Eagle here...` → `["dru eagle here..."]`). Fixed by removing the space: `[A-Za-z0-9_-]`.

3. **`sendText` wrong call signature** — The SDK calls `plugin.outbound.sendText(singleObject)` where the object is `{ text, to, accountId, replyToId, threadId, cfg, identity }`. Our implementation used `(ctx, options)` two-arg signature, so `options` was always `undefined`. This was never caught before because `sendText` was never actually invoked via the `message` tool (only the `llm_output` path was active).

### Fixes Applied

- **`agents-channel.ts`**: Fixed `extractMentions` regex (removed space from char class)
- **`channel.ts`**: 
  - Added `messaging.targetResolver.looksLikeId` to bypass directory lookup for valid vantage slugs
  - Fixed `sendText` and `sendMedia` to use single-object SDK signature
- **`openclaw-plugin-sdk.d.ts`**: Added `OutboundTextParams` type; updated `outbound.sendText/sendMedia` signatures; added `messaging?` field to `VantageChannelPlugin`

### Architecture Note
The `message` tool target resolution flow:
1. `resolveActionTarget` → `resolveChannelTarget` → `resolveMessagingTarget`
2. `resolveMessagingTarget` calls `plugin.messaging.targetResolver.looksLikeId(raw)` first
3. If `true` → bypasses directory lookup, returns `{ ok: true, to: raw }` directly
4. Then `deliverOutboundPayloads` → `createPluginHandler` → calls `plugin.outbound.sendText(singleObj)`
5. Our `sendText` detects `isAgentsChannel` and calls `fanOutAgentsMessage()`

### Verified Working
- `message(channel=vantage, target=clubhouse, message="@Dru ...")` → Dru received and replied
- `vantage.message` RPC path still works as before
- All 7 channel AGENTS.md files have correct native tool instructions
- Build clean throughout

## Additional Bugs Fixed (post-initial fix)

### Bug: JSON blob content in agents channel
`buildEnvelope()` always wraps plain text in `{ messageId, content, role, streaming: false }` object. The storage code was doing `JSON.stringify(envelope.payload)` which produced JSON blobs as message content. Fix: store `parsed.content` directly.

### Bug: Messages appearing on right side (role: "user")
`rpc.ts` `vantage.message` handler stored all messages with `role: "user"` (renders right-side = operator side in Vantage client). Agent messages in the agents channel must use `role: "assistant"`. Fix: check `isAgentsChannel` before storage and set role accordingly.

### Known Limitation: Author name for proactive sends
`params.identity.name` is the SDK's mechanism for agent display name, but it's not populated for vantage-oc sessions. Agent REPLIES via `llm_output` hook have correct author names (from injection record). Proactive sends via `message` tool fall back to "Agent". `agentId` is not surfaced to `sendText()` by the SDK — would need SDK change to fix cleanly.

### AGENTS.md update
Added reply-tagging protocol to all 7 channel AGENTS.md files: when tagged in a message, agents must always tag back the original sender(s) in their reply.

## Agents Channel Routing — Final Architecture (2026-03-14 evening)

### Injection queue (replaces single-slot Map)
`injectionQueues: Map<string, AgentsChannelInjection[]>` in `agents-channel.ts`.
Multiple concurrent fan-outs queue instead of overwriting. Sessions drain one injection per turn.

### Turn-end guard
`recordTurnEnd(sessionKey)` called at every llm_output exit path for `:main` sessions.
`consumeInjection` checks `head.injectedAt < lastTurnEndedAt` — if injection arrived before last turn ended, it was mid-turn; defer. Prevents active conversations being hijacked by A2A fan-outs.
Known edge: ~ms race window between recordTurnEnd and next turn starting. Requires SDK "turn_start" event to fully close. Acceptable in practice.

### Strict mention-based fan-out
Both `fanOutAgentsMessage` and A2A fan-out in `index.ts` use the same guard:
- `@AgentName` → fan only to named agents
- No mentions / `@all` → fan to full roster
- Operator-only mentions (e.g. `@Aaron`) → no fan-out to any agent

### Dynamic operator name
`channel_config` table, `channel_slug='clubhouse'`, `key='operator_name'` → `"Aaron"`.
`buildReplyToList` takes `senderName` param (no hardcoded name).
`fanOutAgentsMessage` reads `operator_name` from channel config when senderName not passed.
A2A fan-out uses `injection.agentName` as senderName for reply-to prefix.

### Reply-to prefix in A2A messages
A2A fan-out now adds `[reply-to: @Sender @OtherAgents]` prefix to injected messages.
Agents know who to address in their reply from the prefix context.
