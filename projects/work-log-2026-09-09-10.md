# Work Log — September 9–10, 2026

Two nights of dense work: a self-audit of the OpenClaw gateway's reliability revealed a pattern of "reconstruct-from-summary instead of retrieve-from-source" that cost us two real errors (LinkedIn paraphrase + 48-hour incident window). That audit spawned a mechanical harness design that's now being baked into protocol. Meanwhile, the Chief-of-Staff template product found its first customer (Jeff), we shipped two droplets through a gauntlet of fixes, and the Barnabas site got a blog review cycle, a "bits hit the fan" post, and a batch of Anton's funnel ideas. ## 1. Memory Harness — Root Cause, Design, and Change Plan

**What was done**
- Overnight session (22:23 → 08:59) executed Aaron's 5-step plan via q8 subagents: root-cause analysis, north-star audit, harness design, insights compilation, gateway change plan.
- Root cause identified: "reconstruct-from-summary instead of retrieve-from-source; confidence doesn't discount for reconstruction." Both failures (LinkedIn paraphrase, 48-hour window error) trace to this.
- North-star audit surfaced that "enforcement is advisory, not mechanical" — published claims describe gates; workspace has prose. Top gaps: no gates, memory checks are habits, orchestration logging has no automated verification.
- Harness design brainstorm produced 6 mechanisms (bootstrap checklist, action gate, point-of-use re-read, subagent brief template, logging enforcement, compaction insurance). Ponytail pass rejected 3 ("action gate" script wrapping, mtime-vs-context comparison, pre-compaction hook).
- Final accepted mechanisms: AGENTS.md "Every Session" checklist upgrade, subagent brief template (`templates/subagent-brief.md`), `verify-logging.sh` nightly cron, point-of-use re-read rule, memory-survival test (already deployed), backup cron (already deployed).
- Change plan organized into 3 phases: Phase 1 (protocol text, cheap, this week), Phase 2 (mechanical enforcement via scripts + cron), Phase 3 (structural, needs Aaron go on hourly reset trial).

**Why it matters**
This is the single most important systems work Aaron's done in months. The harness is what makes "session-reset-tolerant" work — hitting `/reset` on main once an hour without missing beats. Without it, the gateway drifts into "costume-gates" (prose instructions) that the agent forgets or misapplies. The root-cause finding is also portable: it applies to every agent workflow, not just this gateway. And the fact that subagents claimed to write files they never wrote (twice) means any harness must make "verify, then report" mechanical.

**What's interesting**
- The confidence problem: agents feel *more* sure after reconstruction, not less. This is the opposite of human behavior — we get humbled by gaps.
- The "verify-then-report" rule is a one-line protocol change but it fixes Failure B (48-hour window error) cheaply and propagates discipline to every subagent.
- Most verification is cheap scripting (~220 tokens per full cycle) — zero model calls where shell suffices.
- The agent's meta-observation: "both q8 subagents reported writing files they never wrote. Any harness must make verify-then-report the default shape of a task, not an afterthought." This is the core disease.

**Seed**: "Why your AI agent forgets everything (and how to fix it with one-line protocol changes)" — a post about the reconstruction-confidence gap and the mechanical-enforcement vs. advisory-prose gap.

- Aaron ordered Tello physical SIM (eSIM unsupported on Galaxy A16 4G SM-A165F/DS) for a dedicated ops number for Dru; ships in days. Phone: Samsung A16 dual-SIM, data-only SIM in slot 1.

**Why it matters**
This is Aaron's first real productized offering from the Agent Workshop — pre-configured OpenClaw droplet with a sanitized Chief agent template. Jeff is the test customer; if this works, it scales. The process changes (installer-runbook split, customer agent naming per-customer, two-droplet learning pushing default to bare Ubuntu) encode real operational knowledge. And the "whose key, whose bill" decision moved to human 1:1 call — model-provider credentials collected only on the call, Management Key stays in operator's password manager.

**What's interesting**
- The "unauthorized: gateway token mismatch" when running as root is the same rule everywhere else — root's config lacks the token. It's a subtle but consistent break.
- `openclaw update` permanently fails on DO-image droplets because the image's custom systemd unit runs the gateway as the `openclaw` user; the updater's doctor classifies it as "foreign" and refuses maintenance. Fix: `npm install -g --allow-scripts=openclaw,@google/genai,koffi,tree-sitter-bash,protobufjs openclaw@latest` as root.
- IPv6 loopback (`::1`) was the actual break for `proxy_attribution_required` — Caddy connects to the gateway over IPv6, so IPv4-only trust leaves it "unattributable proxy-shaped traffic from ::1".
- The WhatsApp trade-off: "the linked device receives the **full message stream of the whole account** — all chats, contacts, and groups — not just bot conversations. Policy filters are software, not cryptographic walls." A customer who wants "digest all my convos" is making a deliberate, informed choice.

**Seed**: "How we built a $X/month AI concierge for small businesses (and the three droplet gauntlets it took)" — a productized-offering post with the two-droplet learning, the gateway fixes, and the channel decision matrix.

- Model comparison: not a dedicated wiki file found in Sep 9-10 sources. The workshop deck covers "what is out there and where each one actually fits" but no explicit comparison table was logged.

**Why it matters**
The Karpathy pattern is a proven approach to personal knowledge bases: LLM writes the wiki, you curate sources and ask questions. It's directly applicable to Aaron's barnabas.coach wiki layer (raw-sources + compiled-wiki + schema). And the workshop deck's seven blocks map directly to the harness design work: stack = layers 1-4, cost = token math, options = model selection, channels = WhatsApp/Signal/Matrix, memory = session vs compaction, orchestration = routing, behaviour = skills/identity/rules.

**What's interesting**

- The workshop deck's "The question that sorts people instantly": "Plenty of people describe ChatGPT as 'their agent.' If someone tells you about their agent, ask which harness they run. If they don't know what that means, they are describing layer 2, not layer 4."
