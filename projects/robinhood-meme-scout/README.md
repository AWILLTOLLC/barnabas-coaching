# Robinhood Meme Scout

GMGN-powered monitor for Robinhood Chain meme coins. Polls GMGN, applies Aaron's criteria, and DMs alerts + heartbeats to Discord. **v2 (2026-09-05): TikTok scraper removed; GMGN-only rebuild. v2.3 (2026-09-06): DexScreener added as batch outcome source + momentum cross-check. v2.4 (2026-09-06, Warden-inspired): creator status on alerts + Blockscout holder cross-check for finalists.**

## What it does

Every `poll_interval_seconds` (default 60s):
1. Fetches Robinhood-chain tokens from `gmgn-cli` — `market trending`, `market trenches`, `market hot-searches` — and normalizes the three payload shapes into one coin type.
2. Applies **hard gates**: market cap in $500K–$2M or $5M–$25M, age 24–96h, top-10 holders ≤ 40%, no wash-trading flag.
3. Scores 0–100: base 40 + volume (≥$1M +20 / ≥$500K +10) + liquidity (≥$100K +15 / ≥$50K +10) + top10 ≤20% (+10) + mint & freeze renounced (+10) + LP burned (+5).
4. Score ≥ 70 → **momentum check**: rejects the finalist if it's down more than `max_drop_6h_pct` (default 20%) over 6h — catches post-pump dumps that list-payload data can't see (logged as `momentum_reject`). **v2.3:** DexScreener (`tokens/v1/robinhood/...`, chainId `robinhood`, free, no key) is the primary 6h source, GMGN `token info` the fallback and cross-check; when the two disagree (>25% relative on price or >2x on liquidity) a `source_divergence` is logged to `alerts.log` and recorded in `scout.db` — a data-quality signal, never a gate. The daily report counts them. **v2.4 (ideas from [Archive228/warden](https://github.com/Archive228/warden)):** finalists also get (a) the creator's status from GMGN's `dev` block stamped on the alert ("creator exited" / "⚠️ creator pulled LP"), and (b) a Blockscout holder cross-check — top-10 EOA-only share computed against real total supply, compared to GMGN's `top10_rate`; a >2x gap records a `holders` divergence. Contract holders (v4 PoolManager, PonsV2LaunchLocker) are identified by name, which is why wallet-app "top 10" numbers run ~60 points higher than GMGN's.
5. Survivors get a **short LLM thesis** generated by local Ollama (`criteria.json → ollama`, default Qwen3.8-27B Q8): 2–3 hedged sentences on what the coin likely is, its strongest fact, and its biggest risk — built only from GMGN data plus the `chain_context` blurb in criteria.json (update that as the chain's meta rotates). If Ollama is down or slow, the alert still sends, just without the thesis.
6. Discord DM with the full breakdown + thesis, then the address is added to `data/known.json` (never re-alerts).
7. **Chain regime (v2.2, measure-and-stamp):** every scan computes breadth over the trending set (median 1h change, share green, launch rate) and labels the chain hot/neutral/cold — flips need 5 consecutive scans (anti-whipsaw). The label is stamped on every recorded coin, alert, heartbeat, and the daily report (which also breaks gate-passer returns down by regime). It does NOT gate alerts yet; if the outcome data shows regime predicts alert performance, gating becomes a criteria.json change. Thresholds under `regime` in criteria.json.
8. **Feedback loop (v2.1):** every coin seen — rejects included — is recorded once in `data/scout.db` (SQLite, `node:sqlite`) with its full snapshot and evaluation; price/liquidity outcomes are captured at +1h/6h/24h/72h/168h (**v2.3:** one DexScreener batch call covers up to 30 due addresses per tick, GMGN fills misses at ≤5 fetches per tick; each capture row is stamped with its source; 3 failures across both sources = marked dead, itself a rug signal). A **daily report DM at 7am PT** compares median returns across bands (alerted vs near-miss vs rejected), names rejects that ran, counts dead coins, and adds an Ollama narrative suggesting which criteria parameter to review. Criteria changes stay human-approved — edit `criteria.json`, restart. Nothing in this repo trades; execution is manual and stays that way. On-demand: `tsx src/cli.ts report --dry-run`.
9. Heartbeat DM every 4h at 6am/10am/2pm/6pm/10pm PT (silent overnight): coins scanned, gates passed, alerts sent, best non-alert. Silence outside those = something is wrong.

All thresholds live in `criteria.json` — edit it, restart, done. Every evaluated coin is logged to `data/alerts.log` (JSON lines) for tuning.

## Commands

```bash
tsx src/cli.ts scan --dry-run      # one scan, alerts printed not sent
tsx src/cli.ts monitor             # run forever (live DMs)
tsx src/cli.ts monitor --dry-run   # run forever, print instead of DM
tsx src/cli.ts heartbeat-test      # send one heartbeat DM now
npm test                           # unit tests (tsx --test)
```

## Setup

- `gmgn-cli` installed (`/opt/homebrew/bin/gmgn-cli`), API key in `.env` as `GMGN_API_KEY=...`
- Discord bot token read from `~/.openclaw/openclaw.json` (`channels.discord.token`); recipient is Aaron's Discord ID in `src/alerts.ts`.

## Run as a service (launchd)

A template is at `com.apollo.gmgn-scout.plist`. To install:

```bash
cp com.apollo.gmgn-scout.plist ~/Library/LaunchAgents/ && launchctl load ~/Library/LaunchAgents/com.apollo.gmgn-scout.plist
```

Logs go to `data/monitor.log` / `data/monitor.err`. Unload with `launchctl unload ~/Library/LaunchAgents/com.apollo.gmgn-scout.plist`.

## Layout

- `src/config.ts` — criteria + .env loading
- `src/gmgn.ts` — gmgn-cli exec + payload normalizer (shapes pinned by `tests/fixtures/`)
- `src/dexscreener.ts` — DexScreener batch fetch + normalizer (deepest-liquidity pair wins) + divergence check
- `src/blockscout.ts` — Blockscout holder fetch: raw vs EOA-only top-10 shares, contract names (PoolManager, Pons locker)
- `src/dune.ts` — Dune API client for creator launch history (v2.5, needs `DUNE_API_KEY` + saved query from `docs/dune-creator-history.sql`; daily report flags serial deployers)
- `src/filters.ts` — gates + scoring
- `src/heartbeat.ts` — PT slot scheduler
- `src/thesis.ts` — Ollama prompt + generation for alert theses
- `src/alerts.ts` — Discord DM, formatting, JSON log
- `src/monitor.ts` — loop, dedupe, stats
- `legacy/` — v1 TikTok-era code, kept for reference only (broken; do not revive the signer)

## Notes

- GMGN timestamps are Unix **seconds** (v1 treated them as ms — every age was wrong).
- Field quirks: trenches uses `volume_24h`, others use `volume`; trenches has no `creation_timestamp` (falls back to `open_timestamp`).
- No trading of any kind — this repo only watches and alerts.
